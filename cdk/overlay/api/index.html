Overlay

A configurable service for opening floating panels, positioned relative to an origin.

OverviewAPI

Components

OverlayContainerOutlet

No props.

Hooks

useOverlay: () => OverlayHandle

App-facing overlay hook, so apps can build their own overlays (global or flexibleConnectedTo(...) position strategy, scroll strategies, a backdrop + backdropClass, sizing, attaching a component with props) the same way every qwik-material entry point (dialog, bottom sheet, select, menu, autocomplete, tooltip, datepicker, …) already does internally.

Details

Deliberately NOT useContext(OVERLAY) returning a plain Overlay object: Overlay.create/position are ordinary JS closures (over a registry/id-generator), not $() QRLs — Qwik can serialize a QRL reference and a store/signal, but not an arbitrary closure. A real app almost always calls useOverlay() during render and then invokes the result later, from an event handler's own $() scope; capturing a plain Overlay instance that way either fails SSR serialization outright (Code(Q34)) or — if force-marked noSerialize() — silently resolves to undefined after the SSR→CSR resume (confirmed live both ways: this is the same category of pitfall keyboardDispatcher/dialogScrollStrategyFactory already work around by living on QwikCdkInternals as NoSerialize fields instead of being captured directly). The fix, matching useDialog()'s already-proven shape exactly (see qwik-cdk/dialog/dialog.tsx): return an object whose only method is itself a QRL (create$). The QRL's OWN closure captures just ctx (the QwikCdkInternals store — a provided context value, safely serializable) and builds a fresh Overlay INSIDE its own body on every call, never capturing one from outside. The OverlayRef it returns is noSerialize() -wrapped before returning, same convention as MatDialog.open$/ Dialog.open$.

Functions

applyPopoverInsertionPoint(host: HTMLElement, insertionPoint: PopoverInsertionPoint | null | undefined) => void

Mirrors upstream OverlayRef._attachHost()'s insertion-point handling (src/cdk/overlay/overlay-ref.ts): when the overlay renders as a native popover AND its position strategy names a non-'global' insertion point (FlexibleConnectedPositionStrategy.withPopoverLocation('inline' | {type: 'parent', element})), the host element is physically relocated — as a DOM sibling placed immediately after the insertion point element ('inline', e.g. mat-select's cdk-connected-overlay, which anchors its popover right next to the trigger it opens from), or appended as a child of a custom parent element ({type: 'parent', …}) — instead of staying inside the shared .cdk-overlay-container that OverlayContainerOutlet renders it into by default.

Details

Call this ONCE, right after the host's first mount (see overlay-host.tsx's useVisibleTask$) — OverlayHost always renders the host declaratively as a child of .cdk-overlay-container first (Qwik has no imperative "render into this other DOM node" primitive the way upstream's vanilla-DOM _attachHost() does); this performs the same one-time physical move upstream does, via plain DOM APIs. A no-op for the (overwhelmingly common) 'global' case, where insertionPoint is null and the host simply stays where OverlayContainerOutlet put it. Qwik's event delegation (qwikloader attaches listeners at high-level ancestors and resolves the actual target dynamically at dispatch time, not via a fixed subscription captured at listener-attach time) means a plain DOM reparent like this does not break any already-wired on:* handlers on the moved subtree.

createBlockScrollStrategy() => ScrollStrategy

Strategy that prevents the user from scrolling while the overlay is visible.

Details

Uses the cdk-global-scrollblock class on <html> as a guard so a second concurrent block doesn't disturb the saved scroll position.

createCloseScrollStrategy(config?: CloseScrollStrategyConfig) => ScrollStrategy

Strategy that closes the overlay as soon as the user starts scrolling.

Details

Throttle approach: pending flag + setTimeout(0) (leading-edge per task boundary). CDK uses rxjs auditTime(0); for CloseScrollStrategy the functional result is identical because no event data flows out of the handler — both forms run the close check once per task boundary.

createRepositionScrollStrategy(config?: RepositionScrollStrategyConfig) => ScrollStrategy

Strategy that updates the element position as the user is scrolling.

Details

Throttle approach: uses requestAnimationFrame for zero-throttle (smooth, one update per frame), and a setTimeout-based trailing-edge debounce for non-zero throttle values. CDK uses rxjs auditTime(throttle) which emits once at the end of each throttle window; we replicate this with a pending-timer pattern.

createScrollStrategyOptions() => ScrollStrategyOptions
isBuiltinScrollStrategyDescriptor(descriptor: ScrollStrategyDescriptor) => descriptor is BuiltinScrollStrategyDescriptor

True for every ScrollStrategyDescriptor except the QRL escape hatch.

isScrollStrategyInstance(value: ScrollStrategy | ScrollStrategyDescriptor | undefined) => value is ScrollStrategy

True for a real, already-built ScrollStrategy instance (identified structurally — every ScrollStrategy has attach/enable/disable methods; a BuiltinScrollStrategyDescriptor object instead has a type string field, and a QRL is a function, not a plain object), as opposed to a ScrollStrategyDescriptor. Per-call config fields (MatDialogConfig.scrollStrategy, …) accept either shape — a consumer who already has a real instance (e.g. built via useScrollStrategyOptions() directly) can keep passing it unchanged.

resolveBuiltinScrollStrategyDescriptor(descriptor: BuiltinScrollStrategyDescriptor) => ScrollStrategy

Builds the real ScrollStrategy instance a BuiltinScrollStrategyDescriptor names.

resolveConfiguredScrollStrategy(perCall: ScrollStrategy | ScrollStrategyDescriptor | undefined, contextDefault: ScrollStrategyDescriptor) => Promise<ScrollStrategy>

Resolves a per-call ScrollStrategy | ScrollStrategyDescriptor | undefined override against a context-level ScrollStrategyDescriptor default — the shape every one of this port's "open a {dialog,bottom sheet,select,menu, autocomplete} overlay" call sites needs. Always async (see resolveScrollStrategyDescriptor).

resolvePopoverInsertionPoint(usePopover: boolean, positionStrategy: PositionStrategy | undefined) => PopoverInsertionPoint | null

Resolves the insertion point for host, mirroring upstream _attachHost()'s own guard: a custom insertion point only applies when actually rendering as a native popover (usePopover) — for a non-popover overlay the host always stays in the global container regardless of what the position strategy's withPopoverLocation() was configured with.

resolveScrollStrategyDescriptor(descriptor: ScrollStrategyDescriptor) => Promise<ScrollStrategy>

Builds the real ScrollStrategy instance a ScrollStrategyDescriptor names — the built-in cases resolve synchronously (no await actually suspends), the QRL escape hatch invokes and awaits it.

Details

Always returns a Promise (a QRL call always does), so callers that only ever pass the built-in forms and want to stay fully synchronous should use resolveBuiltinScrollStrategyDescriptor directly instead.

OverlayKeyboardDispatcher

Global keydown router. Routes events to the most-recently-added overlay that has a handler installed and whose eventPredicate admits the event.

No props.

OverlayNavigationDispatcher

Global history-navigation router. Qwik-cdk has no Location/Router service to inject (this library takes no router dependency — see OverlayConfig.disposeOnNavigation / MatDialogConfig.closeOnNavigation's own doc comments), so upstream's per-OverlayRef Location.subscribe() becomes a single shared popstate/hashchange listener that broadcasts to EVERY currently-attached overlay — unlike the keyboard/outside-click dispatchers, which route to only the topmost (or the first interested) overlay, a navigation should close every overlay that opted in, not just one.

Details

Deliberately popstate/hashchange ONLY, not every pushState/ replaceState call (which would also fire for in-app link clicks handled by a router calling history.pushState directly — this port's explicit scope is "closes on back/forward navigation", not "closes on every link click").

No props.

OverlayOutsideClickDispatcher

Global pointer-event router. Routes outside-click events to overlays that have a handler installed and whose eventPredicate admits the event.

No props.
