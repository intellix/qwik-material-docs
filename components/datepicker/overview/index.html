Datepicker

A calendar-backed input for picking a single date.

OverviewAPIExamples

The datepicker allows users to enter a date either through text input, or by choosing a date from the calendar. It is made up of several components and a shared picker handle that work together.

Connecting a datepicker to an input

A datepicker is composed of a <MatDatepickerInput> and a calendar pop-up, connected through a shared handle from useMatDatepicker<D>() — called once by a common ancestor, since Qwik has no dependency-injection mechanism to connect several separate elements the way Angular's template reference variables do.

There is also an optional <MatDatepickerToggle> for opening the calendar.

This works either on its own or as part of a <MatFormField>, with the toggle as a prefix or suffix:

const value = useSignal<Date | null>(null);
const picker = useMatDatepicker<Date>({
  onValueChange$: $((v: Date | null) => (value.value = v)),
});

<MatFormField
  label={<MatLabel>Choose a date</MatLabel>}
  control={
    <MatDatepickerInput picker={picker} value={formatDateForDisplay(value.value) || undefined} />
  }
  hintStart={<MatHint>MM/DD/YYYY</MatHint>}
  iconSuffix={<MatDatepickerToggle picker={picker} />}
  infixContent={<MatDatepicker picker={picker} />}
/>;

Date range selection

For a range of dates, use <MatDateRangeInput> with useMatDateRangePicker<D>() and <MatDateRangePicker>/<MatDatepickerToggle> — the same shared-handle shape as the single-date case, just with a DateRange<D> value instead of a D:

const range = useSignal<DateRange<Date>>({start: null, end: null});
const picker = useMatDateRangePicker<Date>({
  onValueChange$: $((v: DateRange<Date>) => (range.value = v)),
});

<MatFormField
  label={<MatLabel>Enter a date range</MatLabel>}
  control={<MatDateRangeInput picker={picker} range={range.value} />}
  iconSuffix={<MatDatepickerToggle picker={picker} />}
  infixContent={<MatDateRangePicker picker={picker} />}
/>;

Confirmation action buttons

Pass your own buttons as the actions prop of <MatDatepicker>/<MatDateRangePicker> to require an explicit confirm before a calendar selection commits. Opening the calendar from code

Upstream's picker.open() / picker.close() are openDatepickerPanel(picker, cdk) / closeDatepickerPanel(picker) (and openDateRangePickerPanel(picker, cdk) for a range), where cdk is read once during render with useContext(QWIK_CDK) from @angular-community/qwik-cdk:

const cdk = useContext(QWIK_CDK);
// e.g. open on focus, like an Angular template's (focus)="picker.open()"
<MatDatepickerInput picker={picker} onFocus$={() => openDatepickerPanel(picker, cdk)} />

Internationalization

Internationalization of the datepicker is configured via three aspects:

  1. The date locale.
  2. The date implementation (DateAdapter) the datepicker uses to parse/format/compare dates.
  3. The display and parse formats (MAT_DATE_FORMATS) used by the datepicker.

All three are provided together by one hook, useMatDateAdapterProvider() — call it once app-wide near your app's root, or scoped to one subtree if called deeper (an inner call shadows an outer one for its own descendants, the same way every other provider hook does). useMatDatepicker()/useMatDateRangePicker()/<MatCalendar>/<MatTimepickerInput> all read from the SAME contexts, so one useMatDateAdapterProvider() call configures the datepicker, the date-range input, and the timepicker together.

Setting the locale

Pass locale to useMatDateAdapterProvider():

export default component$(() => {
  useMatDateAdapterProvider({locale: 'en-GB'});
  return <MyDatepickerPage />;
});

It's also possible to change the locale at runtime: read the same signal any date-aware descendant resolves via useDateLocale() (exported from @angular-community/qwik-material/core) and write to it directly — the Qwik-native equivalent of calling DateAdapter.setLocale(). Every component that renders locale-sensitive text (month/weekday names, the calendar header's period label) re-renders automatically, including an open calendar re-opened after the change:

import {useDateLocale} from '@angular-community/qwik-material/core';

export default component$(() => {
  const locale = useDateLocale();
  return (
    <MatButton onClick$={$(() => { locale.value = 'fr'; })}>
      Switch to French
    </MatButton>
  );
});

Choosing a date implementation and date format settings

This port ships one DateAdapter implementation: NativeDateAdapter, backed by the native Date object and Intl for formatting (no Moment/Luxon/date-fns dependency). It's the default for every date-aware component — nothing needs to be provided to use it.

import {NativeDateAdapter, MAT_NATIVE_DATE_FORMATS} from '@angular-community/qwik-material/core';

provideNativeDateAdapter()'s equivalent here is simply not calling useMatDateAdapterProvider() at all (or calling it without a factory/formats key) — every date-aware component already resolves NativeDateAdapter/MAT_NATIVE_DATE_FORMATS with no provider.

If you need custom parsing/formatting behavior (for example, an app whose users type dates as dd.mm.yyyy), subclass NativeDateAdapter and override parse()/format() — every other method (arithmetic, comparisons, locale-aware names, time parsing/formatting) is inherited for free, so the same subclass works for the datepicker input, the date-range input, and the timepicker:

import {$, component$} from '@qwik.dev/core';
import {
  NativeDateAdapter,
  useMatDateAdapterProvider,
  type MatDateFormats,
} from '@angular-community/qwik-material/core';

class DotDateAdapter extends NativeDateAdapter {
  override parse(value: unknown, parseFormat: unknown): Date | null {
    if (typeof value === 'string') {
      const match = value.trim().match(/^(\d{1,2})\.(\d{1,2})\.(\d{4})$/);
      if (match) {
        const [, dd, mm, yyyy] = match;
        return this.createDate(Number(yyyy), Number(mm) - 1, Number(dd));
      }
    }
    return super.parse(value, parseFormat);
  }

  override format(date: Date, displayFormat: unknown): string {
    if (displayFormat === 'DD.MM.YYYY') {
      const dd = String(this.getDate(date)).padStart(2, '0');
      const mm = String(this.getMonth(date) + 1).padStart(2, '0');
      return `${dd}.${mm}.${this.getYear(date)}`;
    }
    return super.format(date, displayFormat);
  }
}

const DOT_DATE_FORMATS: MatDateFormats = {
  parse: {dateInput: 'DD.MM.YYYY'},
  display: {
    dateInput: 'DD.MM.YYYY',
    monthYearLabel: {year: 'numeric', month: 'short'},
    dateA11yLabel: {year: 'numeric', month: 'long', day: 'numeric'},
    monthYearA11yLabel: {year: 'numeric', month: 'long'},
  },
};

export default component$(() => {
  useMatDateAdapterProvider({
    factory: $((locale: string) => new DotDateAdapter(locale)),
    formats: DOT_DATE_FORMATS,
  });
  return <MyDatepickerPage />;
});

factory takes a factory (QRL<(locale: string) => DateAdapter<D>>), never a live adapter instance — a class instance with methods can't be put into Qwik's serializable resumable state, so every date-aware component resolves the factory into a fresh instance wherever one is actually needed (parsing typed text, formatting a value to display) rather than holding one across a render. This is transparent to you as a consumer; it only matters if you're extending the port itself (see datepicker/SYNC.md's "DateAdapter / MAT_DATE_FORMATS / MAT_DATE_LOCALE / dateClass" section for the full design).

Not ported: alternate date-library adapters (date-fns/Luxon/Moment) — only the native Date-based adapter (and your own subclasses of it) are supported.

Highlighting specific dates

If you want to apply one or more CSS classes to some dates in the calendar (e.g. to highlight a holiday), pass dateClass to useMatDatepicker()/useMatDateRangePicker(). It accepts a QRL function called with each date in the calendar (and which view it belongs to); any classes it returns (a string, string array, Set, or a record of class name to boolean, same as upstream's ngClass-compatible return value) are applied to that date's cell:

const picker = useMatDatepicker<Date>({
  dateClass: $((cellDate: Date, view: 'month' | 'year' | 'multi-year') => {
    if (view === 'month' && cellDate.getDate() === 1) return 'month-start';
    return '';
  }),
});

Accessibility

The datepicker pop-up uses the role="dialog" pattern; the calendar itself implements role="grid". Always provide an accessible label for the input (<MatLabel>, aria-label, or aria-labelledby), and communicate the expected date format via a hint.

<MatDatepickerInput>/<MatDatepickerToggle> both apply aria-haspopup to their native elements.

Angular → Qwik notes

  • A shared picker handle, not template-reference-variable DI. useMatDatepicker<D>()/ useMatDateRangePicker<D>() are called once by a common ancestor and passed as a picker prop to <MatDatepickerInput>/<MatDateRangeInput>/<MatDatepickerToggle>/<MatDatepicker>/ <MatDateRangePicker> — see the first section above.
  • No ControlValueAccessor/bundled forms. touched/dirty/invalid are plain props you compute yourself (see useMatFormControl(), or Using with Formisch).
  • (dateInput)/(dateChange) collapse into one onValueChange$ — see "Input and change events" above.
  • Pluggable DateAdapter/MAT_DATE_FORMATS/locale, and dateClass, are ported — see "Internationalization"/"Highlighting specific dates" above. matDateAdapterFactory is a QRL factory, not a live adapter instance (a class instance can't be put into Qwik's serializable resumable state); useDateLocale() returns a reactive Signal<string> in place of upstream's one-shot MAT_DATE_LOCALE DI token + imperative setLocale() call.
  • Not ported: alternate date-library adapters (date-fns/Luxon/Moment — only NativeDateAdapter/its subclasses), localized MatDatepickerIntl strings, yearSelected/monthSelected outputs, comparison ranges, custom range selection strategies, a custom calendar header component, and the imperative open()/close()/opened API — see the relevant sections above and Migrating from Angular Material.
  • No dev-mode throws — an unsupported combination (e.g. options-shaped misuse) doesn't throw; it simply produces whatever DOM the data implies.
