Progress Bar

A horizontal bar showing the progress of an operation, determinate or not.

OverviewAPIExamples

<MatProgressBar> is a horizontal progress-bar for indicating progress and activity.

Progress mode

The progress-bar supports four modes: determinate, indeterminate, buffer and query.

Determinate

Operations where the percentage of the operation complete is known should use the determinate indicator.

progress-bar-determinateOpen in Angular docs

This is the default mode and the progress is represented by the value prop.

Indeterminate

Operations where the user is asked to wait while something finishes and it's not necessary to indicate how long it will take should use the indeterminate indicator.

progress-bar-indeterminateOpen in Angular docs

In this mode the value prop is ignored.

Buffer

Use the buffer mode of the progress-bar to indicate some activity or loading from the server.

progress-bar-bufferOpen in Angular docs

In "buffer" mode, value determines the progress of the primary bar while bufferValue is used to show the additional buffering progress.

Query

Use the query mode of the progress-bar to indicate pre-loading before the actual loading starts.

progress-bar-queryOpen in Angular docs

In "query" mode, the progress-bar renders as an inverted "indeterminate" bar. Once the response progress is available, mode should be changed to determinate to convey the progress. In this mode the value prop is ignored.

Accessibility

<MatProgressBar> implements the ARIA role="progressbar" pattern. By default, the progress bar sets aria-valuemin to 0 and aria-valuemax to 100. Avoid changing these values, as this may cause incompatibility with some assistive technology.

Always provide an accessible label via the aria-label or aria-labelledby prop for each progress bar.

Angular → Qwik notes

  • animationEnd: EventEmitter<{value: number}> → onAnimationEnd$?: QRL<(value: number) => void> prop. Attached lazily via useOn('transitionend', ...) on the host — no per-instance useVisibleTask$, and the handler chunk only loads the first time a transition actually completes (never for indeterminate/query). Same filter as upstream: fires only when the event's target is the primary bar and mode is determinate/buffer.
  • ThemePalette narrowed to 'primary' | 'accent' | 'warn' as MatProgressBarColor.
  • .mat-progress-bar-reduced-motion class omitted — the SCSS's own @media (prefers-reduced-motion: reduce) rule covers it without a client-side matchMedia check.
  • Global defaults via a hook (useMatProgressBarProvider()), not an MAT_PROGRESS_BAR_CONFIG injection token.
  • Harness not ported.
