Radio Button

A single selection from a set of mutually exclusive options.

OverviewAPIExamples

<MatRadioButton> provides the same functionality as a native <input type="radio"> enhanced with Material Design styling and animations.

radio-overviewOpen in Angular docs

All radio-buttons with the same name comprise a set from which only one may be selected at a time.

Radio-button label

The radio-button label is provided as the content to the <MatRadioButton> element. The label can be positioned before or after the radio-button by setting the labelPosition prop to 'before' or 'after'.

If you don't want the label to appear next to the radio-button, you can use aria-label or aria-labelledby to specify an appropriate label.

Radio groups

Radio-buttons should typically be placed inside of a <MatRadioGroup> unless the DOM structure would make that impossible (e.g., radio-buttons inside of table cells). The radio-group has a value prop that reflects the currently selected radio-button inside of the group.

Individual radio-buttons inside of a radio-group will inherit the name of the group.

Use with forms

There is no Angular Forms integration in this port — <MatRadioGroup> is a controlled component: pass value as a prop and read changes back through onChange$.

<MatRadioGroup value={selected.value} onChange$={e => (selected.value = e.value)}>
  <MatRadioButton value="1">Option 1</MatRadioButton>
  <MatRadioButton value="2">Option 2</MatRadioButton>
</MatRadioGroup>

A form library can still drive the ng-touched/ng-untouched, ng-pristine/ng-dirty, ng-valid/ng-invalid classes Angular's NgControlStatus would add to <mat-radio-group formControlName="..."> — pass formBound plus touched/dirty/invalid (booleans you compute yourself) and onTouched$. onTouched$ fires on blur of ANY radio in the group, matching upstream's own per-button FocusMonitor subscription — including when focus just moves to another radio in the same group:

<MatRadioGroup
  value={field.value.value}
  formBound
  touched={field.touched.value}
  dirty={field.dirty.value}
  invalid={field.invalid.value}
  onChange$={v => {
    field.dirty.value = true;
    field.value.value = v;
  }}
  onTouched$={() => (field.touched.value = true)}
>
  <MatRadioButton value="1">Option 1</MatRadioButton>
  <MatRadioButton value="2">Option 2</MatRadioButton>
</MatRadioGroup>

See Using with Formisch for a worked example with a real form library.

Accessibility

<MatRadioButton> uses an internal <input type="radio"> to provide an accessible experience. This internal radio button receives focus and is automatically labelled by the text content of the <MatRadioButton> element. Avoid adding other interactive controls into the content of <MatRadioButton>, as this degrades the experience for users of assistive technology.

Always provide an accessible label via the aria-label, aria-labelledby, or aria-describedby prop for radio buttons without descriptive text content.

<MatRadioButton aria-label={getMultipleChoiceAnswer()} />

Prefer placing all radio buttons inside of a <MatRadioGroup> rather than creating standalone radio buttons because groups are easier to use exclusively with a keyboard.

You should provide an accessible label for all <MatRadioGroup> elements via aria-label or aria-labelledby.

Angular → Qwik notes

  • UniqueSelectionDispatcher removed. A grouped button recomputes checked from the shared group context's value on every render, so unchecking a previously-selected sibling is just normal reactivity. A standalone button (no group) keeps one lazy document change listener instead, since native radio change events already bubble there for free — the Qwik-native shape of the same cross-component notice upstream's dispatcher provided.
  • No Angular Forms integration. ControlValueAccessor/NG_VALUE_ACCESSOR/ngModel/ FormControl have no Qwik equivalent — replaced by the controlled-component pattern above. formBound/touched/dirty/invalid/onTouched$ mirror upstream's NgControlStatus host classes (on the GROUP, never an individual button — matching upstream exactly) and _touch() timing (see "Use with forms" above), but invalid is always a plain boolean YOU compute.
  • EventEmitter change removed from both the group and the button — replaced by onChange$ QRL props, no MatRadioChange event object (the payload is just the new value).
  • checked is a live DOM property, not an attribute — same category of SSR-vs-CSR gap as checkbox; handled internally, transparent to consumers.
  • No imperative .focus() on the host element. The host's (focus)-forwarding listener isn't ported — no scenario calls .focus() on the custom element directly.
  • Global defaults via a hook (useMatRadioProvider()), not an MAT_RADIO_DEFAULT_OPTIONS injection token.
  • Harness not ported.
