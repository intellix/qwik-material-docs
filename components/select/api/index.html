Hooks

useMatSelectProvider: (providerConfig?: MatSelectProviderConfig) => void

Provides {@link MAT_SELECT_CONFIG} and {@link MAT_SELECT_SCROLL_STRATEGY} for this subtree — call once near the root (or anywhere deeper, to override just that part of the tree) so every MatSelect descendant resolves its defaults/scroll strategy from providerConfig instead of the hardcoded fallbacks. Only these two contexts are provided; every other qwik-material configuration context stays whatever an ancestor (or nothing) already provided.

Types

MatSelectConfig

Defaults applied to every MatSelect in a subtree that doesn't set its own. Mirrors upstream's MatSelectConfig + MAT_SELECT_CONFIG injection token (src/material/select/select.ts). Consumers provide this via useMatSelectProvider({config: {...}}).

Details

disableOptionCentering/canSelectNullableOptions are accepted for API parity but unused by this port — see select/SYNC.md's deviations list. canSelectNullableOptions has no scenario exercising it; disableOptionCentering is a genuine upstream no-op in Material 21.2 — VERIFIED by reading select.ts directly: the field is declared (@Input() disableOptionCentering = this._defaultOptions ?.disableOptionCentering ?? false) and stored, but grep-confirmed to be read NOWHERE else in the class — it only ever affected the pre-FlexibleConnectedPositionStrategy positioning math Angular Material removed entirely in a much earlier major version. This port's own earlier doc comment here described it as affecting "non-flexible positioning math this port doesn't replicate", which was imprecise (implying the port was the one dropping behavior) — upstream itself has nothing left to drop in 21.2.
