Select

A Material-styled dropdown select control, usable inside a <MatFormField>.

OverviewAPIExamples

<MatSelect> is a form control for selecting a value from a set of options, similar to the native <select> element. You can read more about selects in the Material Design spec. It's designed to work inside of a <MatFormField> element.

Options are passed as plain data via the options prop — an array of {value, label, ...} entries — rather than as nested child elements:

<MatFormField
  label={<MatLabel>Favorite food</MatLabel>}
  control={
    <MatSelect
      controlType="mat-select"
      options={[
        {value: 'steak', label: 'Steak'},
        {value: 'pizza', label: 'Pizza'},
        {value: 'tacos', label: 'Tacos'},
      ]}
    />
  }
/>

MatSelect renders <MatOption> internally for each entry; content (instead of label) lets one option render richer JSX (e.g. with a leading icon) while label still supplies the plain-text value used for the trigger and keyboard typeahead.

Getting and setting the select value

MatSelect supports 2-way binding via the value prop + onValueChange$. Note that value is read only ONCE, at first render, to set the initial selection — pass new values through onValueChange$'s own round trip (store the current value in your own signal and reflect it back) rather than expecting a later change to the value prop itself to move the selection.

Setting a static placeholder

The placeholder is text shown when the <MatFormField> label is floating but the select is empty. Set it via the placeholder prop.

Disabling the select or individual options

Pass disabled on <MatSelect> to disable the whole control, or set disabled: true on an individual entry in options to disable just that option (or a whole group, via the group entry's own disabled).

Creating groups of options

Give an options entry an options array of its own (instead of a value) to render it as a group — MatOptgroup, with the entry's label as the group subheading:

options={[
  {label: 'Fruit', options: [{value: 'apple', label: 'Apple'}, {value: 'pear', label: 'Pear'}]},
  {label: 'Vegetables', options: [{value: 'carrot', label: 'Carrot'}]},
]}

Multiple selection

Pass the multiple prop to allow selecting more than one value at once — value/ onValueChange$ then deal in arrays instead of a single value. Unlike upstream, this port doesn't guard against changing multiple dynamically after the first render (no current scenario relies on that), so avoid toggling it on a live instance.

Comparing objects

By default MatSelect uses the === operator to determine whether an option is selected. With objects, this means that a new object, even if it has the same properties, is not considered equal. If an option needs to be selected based on an identifying property (e.g. its id), set compareWith to a function accepting two option values and returning whether they should be considered equal:

<MatSelect
  controlType="mat-select"
  value={selectedFood.value}
  onValueChange$={(v) => (selectedFood.value = v)}
  compareWith$={$((o1: Food, o2: Food) => o1?.id === o2?.id)}
  options={foods.map((f) => ({value: f, label: f.name}))}
/>

compareWith$ must be a QRL (wrap it in $(...)) so it survives resume — a plain function can't cross the SSR→client boundary. It's used for both single- and multiple-mode selection, and on every initial-value match, matching upstream MatSelect.compareWith exactly (including argument order: the option's own value first, the value being matched against it second).

Accessibility

When possible, prefer a native <select> element over MatSelect — it provides the most accessible experience across the widest range of platforms.

MatSelect implements the combobox pattern from the ARIA 1.2 specification: the trigger controls a role="listbox" element opened in a pop-up. Because the pop-up uses the listbox pattern, don't put other interactive controls (buttons, checkboxes) inside an option — this interferes with most assistive technology.

Always provide an accessible label: a <MatLabel> inside <MatFormField>, or the aria-label / aria-labelledby prop directly on <MatSelect>.

By default, MatSelect shows a checkmark to identify selected items. hideSingleSelectionIndicator hides it for single-selection mode, at the cost of making selected items harder to identify visually — use with care.

Angular → Qwik notes

  • Options are data, not projected content. Angular projects <mat-option> elements as children of <mat-select>; qwik-material instead takes a plain options: MatSelectEntryDef[] prop ({value, label, content?, disabled?}, or {label, options: [...]} for a group) — MatOption/MatOptgroup still exist as components but MatSelect renders them internally from this data rather than you nesting them by hand.
  • value is read once, not live. Unlike most qwik-material props, writing a new value into the value prop after first render does not move the selection — drive changes through onValueChange$'s own round trip instead.
  • compareWith is now compareWith$, a QRL, not a plain function — see "Comparing objects" above.
  • errorStateMatcher is ported — see Form field → Error messages. It accepts 'touched'/'dirty' (the two upstream built-in matchers) or a QRL<(state) => boolean> for a custom one — never a class instance.
  • Not ported: disableRipple.
  • canSelectNullableOptions exists on MatSelectConfig for API shape parity but currently has no effect — no scenario in this port exercises it. disableOptionCentering is accepted (both via MatSelectConfig and directly on <MatSelect>) but is a genuine upstream no-op in Material 21.2 — it has no effect there either (verified by reading select.ts: the field is declared but read nowhere else), not something this port chose to drop.
  • No native <select matNativeControl> support. <MatInput> doesn't implement a native-select mode; a form field with a native <select> needs its own small control component implementing the same MatFormFieldControlProps contract MatInput/MatSelect do (see Form Field → Custom form field controls).
