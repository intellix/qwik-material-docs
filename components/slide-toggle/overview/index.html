Slide Toggle

An on/off control, like a switch.

OverviewAPIExamples

<MatSlideToggle> is an on/off control that can be toggled via clicking.

slide-toggle-overviewOpen in Angular docs

The slide-toggle behaves similarly to a checkbox, though it does not support an indeterminate state like <MatCheckbox>.

Slide-toggle label

The slide-toggle label is provided as the content to the <MatSlideToggle> element.

If you don't want the label to appear next to the slide-toggle, you can use aria-label or aria-labelledby to specify an appropriate label.

Use with forms

There is no Angular Forms integration in this port — see Angular → Qwik notes below for the controlled-component replacement.

A form library can still drive the ng-touched/ng-untouched, ng-pristine/ng-dirty, ng-valid/ng-invalid classes Angular's NgControlStatus would add to <mat-slide-toggle formControlName="..."> — pass formBound plus touched/dirty/invalid (booleans you compute yourself) and onTouched$ (called on blur of the inner button, same timing as upstream's _onTouched()):

<MatSlideToggle
  checked={field.checked.value}
  formBound
  touched={field.touched.value}
  dirty={field.dirty.value}
  invalid={field.invalid.value}
  onChange$={next => {
    field.dirty.value = true;
    field.checked.value = next;
  }}
  onTouched$={() => (field.touched.value = true)}
>
  Send me the monthly newsletter
</MatSlideToggle>

See Using with Formisch for a worked example with a real form library.

Accessibility

<MatSlideToggle> uses an internal <button role="switch"> to provide an accessible experience. This internal button receives focus and is automatically labelled by the text content of the <MatSlideToggle> element. Avoid adding other interactive controls into the content of <MatSlideToggle>, as this degrades the experience for users of assistive technology.

Always provide an accessible label via the aria-label or aria-labelledby prop for toggles without descriptive text content.

<MatSlideToggle aria-label={isSubscribedToEmailsMessage} />

Angular → Qwik notes

  • No Angular Forms integration. ControlValueAccessor/Validator (NG_VALUE_ACCESSOR/NG_VALIDATORS) have no Qwik equivalent — replaced by the controlled-component pattern: the consumer owns checked via a signal and passes it as a prop, reading changes back through onChange$/onToggleChange$ QRL props (no .emit() EventEmitter API). formBound/touched/dirty/invalid/onTouched$ mirror upstream's NgControlStatus host classes + the FocusMonitor-driven _onTouched() timing (see "Use with forms" above), but invalid is always a plain boolean YOU compute.
  • No imperative focus()/toggle() methods — Qwik has no exported component-instance handle; drive all interaction through real clicks/Tab/Space.
  • required only drives aria-required on the inner button — there's no native form-participation gap to replicate (the interactive element is a <button>, not an <input>, same as MatButtonToggle).
  • color kept as a plain string, not a typed ThemePalette — matches upstream's own comment that the typed version "has no effect in M3 themes" anyway.
  • No RTL support — the synced SCSS's [dir='rtl'] rules are currently unreachable dead code.
  • Global defaults via a hook (useMatSlideToggleProvider()), not an MAT_SLIDE_TOGGLE_CONFIG injection token.
  • Harness not ported.

Known pre-existing DOM-parity gap: the slide-toggle-overview docs example wraps each <mat-slide-toggle> in a <p>. <MatSlideToggle>'s required inner markup includes a <div> (shared with checkbox/radio), and per the HTML5 parsing algorithm a <div> start tag implicitly closes any open <p> once the browser parses Qwik's SSR'd HTML — Angular's dev-app is pure CSR (built via Renderer2 DOM calls, never HTML-string parsing) so it never hits this rule. Tracked as an EXPECTED_FAILURES entry in the parity suite, not a Qwik bug.
