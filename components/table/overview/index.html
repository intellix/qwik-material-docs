Table

A data table with sorting, pagination, and row selection, built on the CDK table.

OverviewAPIExamples

MatTable provides a Material Design styled data-table that can be used to display rows of data.

This table builds on the foundation of the CDK data-table and uses a similar interface for its data input, except that columns/rows are passed as plain data instead of projected templates (see Angular → Qwik notes below).

1. Write your columns and rows

Provide a columns: MatColumnDef[] array (one entry per column, each with a name and optional header/footer content) and a rows: MatTableRow[] array (one entry per data row, with cells already evaluated per row by your own .map() over your data array).

const columns: MatColumnDef[] = [{name: 'score', header: 'Score'}];
const rows: MatTableRow[] = users.map(user => ({key: user.id, cells: {score: user.score}}));

2. Define the row templates

Tell <MatTable> which columns to render via displayedColumns — a plain array of column names, in the order you want them rendered. The same list of columns can be reordered or filtered simply by changing this array.

<MatTable columns={columns} rows={rows} displayedColumns={['userName', 'age']} />

Advanced data sources

qwik-material has no MatTableDataSource/DataSource abstraction — see Angular → Qwik notes. Sorting, filtering, and pagination logic is implemented directly by the consumer, operating on a plain array before it's passed to rows.

Styling Columns

Each table cell has an automatically generated class based on which column it appears in. The format for this generated class is mat-column-NAME. For example, cells in a column named "symbol" can be targeted with the selector .mat-column-symbol.

Row Templates

Upstream lets you bind event handlers/properties directly on the row template, applied to every rendered row. qwik-material exposes the same behavior on each MatTableRow entry directly: onClick$ mirrors (click) on <tr mat-row>, and class mirrors [class.x]. Per-cell overrides (a class, or a native-table-only colSpan) are a sibling cellProps field, keyed by column name, so cells itself stays content-only.

table-row-bindingOpen in Angular docs

Features

MatTable is focused on a single responsibility: efficiently render rows of data in a performant and accessible way.

You'll notice that the table itself doesn't come out of the box with a lot of features, but expects that the table will be included in a composition of components that fills out its features.

For example, you can add sorting and pagination to the table by using MatSort (via the column's sortHeader field) and MatPaginator, mutating the data provided to the table according to their callbacks.

Pagination

To paginate the table's data, add a <MatPaginator> after the table and slice your data array by its onPage$ callback's pageIndex/pageSize.

Sorting

To add sorting behavior to the table, pass sortHeader: true (or {id}) on a column's MatColumnDef, and pass sort={{...}} on <MatTable> itself (see the Sort overview's Angular → Qwik notes for why this is one shared element instead of two directives).

Filtering

qwik-material does not provide a specific component to be used for filtering MatTable since there is no single common approach to adding a filter UI to table data.

A general strategy is to add an input where users can type in a filter string and filter your own data array before it's passed to rows. If you want to show a message when no data matches the filter, pass noData on <MatTable>.

Sticky Rows and Columns

By using position: sticky styling, the table's rows and columns can be fixed so that they do not leave the viewport even when scrolled. Pass sticky: true on a headerRows/footerRows entry, or sticky/stickyEnd on a column's MatColumnDef.

In order to fix the header row to the top of the scrolling viewport containing the table, pass headerRows={[{columns: displayedColumns, sticky: true}]}.

Multiple row templates (expandable rows)

Upstream's multiTemplateDataRows lets a single data object render as multiple <tr>s — e.g. a main row plus a "detail" row that expands below it. There's no separate boolean to set: a MatTableRow entry's own columns field overrides which columns THAT row renders (falling back to displayedColumns), so you simply place more than one MatTableRow per data item in the flat rows array — a main row using the regular columns, immediately followed by a detail row using a single different column that spans the full width via cellProps.<name>.colSpan.

Accessibility

By default, MatTable applies role="table". Always provide an accessible label for your tables via aria-label or aria-labelledby on the table element.

Tables with display: flex

MatTable does not require that you use a native HTML table. Instead, pass as="mat-table" for an alternative approach that uses display: flex for the table's styles.

<MatTable as="mat-table" columns={columns} rows={rows} displayedColumns={displayedColumns} />

Angular → Qwik notes

  • Columns and rows are plain data (columns/rows arrays), not content-projected <ng-container matColumnDef>/*matCellDef templates. Upstream's mat-table takes CONTENT CHILDREN, queried via @ContentChildren and manufactured into rows via ViewContainerRef.createEmbeddedView. Qwik has no equivalent, and a column's cell template is applied once per data row AND independently as a header/footer, so this port generalizes the "data array carrying already-realized JSXOutput" pattern (already used by MatTabGroup/ MatStepper) to two dimensions: columns: MatColumnDef[] (one entry per matColumnDef, header/footer already-built content, same for every row) and rows: MatTableRow[] (one entry per data row, with cells already evaluated per row by your own .map()).
  • No MatTableDataSource. Confirmed genuinely unused by every scenario in this port's contract — every one uses a plain array, re-sorted/mutated by the consumer's own code. A future consumer wanting the built-in filter/sort/paginate pipeline would need this ported separately.
  • matSort/mat-header-cell combine into one sortHeader field on MatColumnDef. Upstream attaches TWO directives to the SAME <th>; Qwik renders exactly one element per cell, so MatColumnDef.sortHeader tells <MatTable> to render a <MatSortHeader> directly as the header cell instead.
  • Per-row class/click handler and per-cell class/colSpan are plain fields on MatTableRow, not a directive on a row template. onClick$/class on MatTableRow mirror (click)/ [class.x] on <tr mat-row>; cellProps.<name>.{class, colSpan} mirrors a cell-level binding, kept as a sibling to cells (content-only) rather than widening its value type.
  • No virtual scrolling. @angular/cdk/scrolling has no qwik-cdk entry point yet.
  • No drag-and-drop column/row reordering. @angular/cdk/drag-drop has no qwik-cdk entry point yet.
  • multiTemplateDataRows has no separate boolean — it's just more than one MatTableRow per data item. This port's flat, consumer-built rows array already allows any number of row entries per data item (each with its own columns override); there's nothing to flip on.
  • No MatRipple on table rows. Not yet wired up for the row-data shape this port uses.
