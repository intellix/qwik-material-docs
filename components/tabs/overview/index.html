Tabs

Organizes content into separate views, one visible at a time.

OverviewAPIExamples

qwik-material tabs organize content into separate views where only one view can be visible at a time. Each tab's label is shown in the tab header and the active tab's label is designated with the animated ink bar. When the list of tab labels exceeds the width of the header, pagination controls appear to let the user scroll left and right across the labels.

The active tab may be set using the selectedIndex prop or when the user selects one of the tab labels in the header.

Events

The onSelectedIndexChange$ callback fires when the active tab changes (the two-way-binding half of selectedIndex).

The onFocusChange$ callback fires when the user puts focus on any of the tab labels in the header, usually through keyboard navigation.

Dynamic Height

By default, the tab group will not change its height to the height of the currently active tab. To change this, pass dynamicHeight. The tab body will animate its height according to the height of the active tab.

Tabs and navigation

While <MatTabGroup> is used to switch between views within a single route, <MatTabNav> provides a tab-like UI for navigating between routes.

<MatTabNav> is not tied to any particular router; it works with normal <a>-style links (via <MatTabLink>) and uses the active prop to determine which tab is currently active. The corresponding content must be wrapped in a <MatTabNavPanel>, wired to its <MatTabNav> via a shared id (see Angular → Qwik notes below) and should typically be placed relatively close to the <MatTabNav> (see Accessibility).

Keeping the tab content inside the DOM while it's off-screen

By default <MatTabGroup> will remove the content of off-screen tabs from the DOM until they come into view. This is optimal for most cases since it keeps the DOM size smaller, but it isn't great for others, like when a tab has an <audio> or <video> element, because the content will be re-initialized whenever the user navigates to the tab. If you want to keep the content of off-screen tabs in the DOM, pass preserveContent.

Start the video in the first tab and navigate to the second one to see how it keeps playing.

Accessibility

MatTabGroup and MatTabNav both implement the ARIA Tabs design pattern. Both compose tablist, tab, and tabpanel elements with handling for keyboard inputs and focus management.

When using MatTabNav, you should place the <MatTabNavPanel> relatively close to if not immediately adjacent to the <MatTabNav> so that it's easy for screen reader users to identify the association.

Labels

Always provide an accessible label via ariaLabel or ariaLabelledby for tabs without descriptive text content.

Keyboard interaction

MatTabGroup and MatTabNav both implement the following keyboard interactions:

Shortcut Action
Left Arrow Move focus to previous tab
Right Arrow Move focus to next tab
Home Move focus to first tab
End Move focus to last tab
Space or Enter Switch to focused tab

Angular → Qwik notes

  • Tabs are a data array (tabs: MatTabDef[]), not <MatTab> children. Upstream's <mat-tab>/<ng-template mat-tab-label> are content-projected and queried via @ContentChildren; Qwik can't inspect a <Slot/>'s projected children's shape the same way. <MatTabGroup tabs={[{label, labelTemplate, content, disabled, ...}]}> carries the same per-tab data as a plain array instead — see MatTabDef's own fields for the full set (mirrors MatTab's inputs 1:1).
  • No separate "lazy content" prop/directive. Upstream's <ng-template matTabContent> opts a tab INTO lazy initialization (plain content is eager by default); in this port, EVERY tab's content is already lazy — only rendered once that tab first centers (and detached again on leaving, unless preserveContent) — observably identical to upstream's own lazy behavior, so there's no separate mechanism to opt into.
  • MatTabNav ↔ MatTabNavPanel wiring is a plain id you thread through yourself, not an automatic template-variable ([tabPanel]="tabPanel") reference. Pass the same id as <MatTabNav tabPanelId={id}> and <MatTabNavPanel id={id}>; <MatTabNavPanel activeTabId={...}> likewise needs the active link's id supplied explicitly (there's no instance back-reference for MatTabNav to mutate on its own, as upstream's does internally).
  • Sortable tabs (drag-drop reordering) aren't ported. No @angular/cdk/drag-drop entry point exists in qwik-cdk yet.
