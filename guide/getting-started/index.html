Getting started

@angular-community/qwik-material and @angular-community/qwik-cdk are a Qwik port of Angular Material and the Angular CDK. If you know Angular Material, the component APIs will look familiar — props instead of @Input()s, $-suffixed handler props instead of @Output()s, and hooks instead of structural/attribute directives.

Requirements

  • Qwik v2. @qwik.dev/core >=2.0.0-rc.4 (and @qwik.dev/router if you're using file-based routing) as peer dependencies. Both packages were upgraded from Qwik 1.x to v2 on 2026-11-01 — if your app is still on Qwik 1 (@builder.io/qwik), upgrade first (qwik migrate-v2, see next.qwik.dev/docs/upgrade).
  • Current, MDC-based Angular Material concepts. This port targets @angular/material@21.2.14 — the current, MDC-based component architecture. Legacy (pre-MDC) Material components and APIs are not supported; there's nothing to migrate from if your Angular app is already on a current Material version.

Install

pnpm add @angular-community/qwik-cdk @angular-community/qwik-material

(or npm install / yarn add — both are plain workspace packages with @qwik.dev/core as a peer dependency).

Wire up your app root

Every qwik-material component reads shared state (the overlay container, open dialogs, text direction, a monotonic id generator) from context that <QwikCdkRoot> provides. It must wrap your whole app exactly once, near the root — the same role Angular's root injector plays for CDK services. This is the one piece of setup you can't do with a hook (it also renders the overlay container element itself, not just context):

// src/root.tsx
import {component$} from '@qwik.dev/core';
import {QwikCdkRoot} from '@angular-community/qwik-cdk';

export default component$(() => (
  <QwikCdkRoot>
    {/* the rest of your app */}
  </QwikCdkRoot>
));

<QwikCdkRoot> takes a few optional props: dialogDefaults (default MatDialogConfig overrides), overlayContainer (where overlay content attaches), direction ('ltr' | 'rtl').

Every component-family default (icon font set, dialog/bottom-sheet/select/menu/autocomplete config + scroll strategy, the app-wide ErrorStateMatcher, ripple options, the date adapter, …) is configured with a hook, not a wrapper component — there's no single "provider" component to reach for. Each hook provides ONLY its own setting, so calling one never resets anything else an ancestor already configured — call as many as you need, in a root layout component, right under <QwikCdkRoot>:

// src/routes/layout.tsx
import {component$, Slot} from '@qwik.dev/core';
import {useMatProviders} from '@angular-community/qwik-material/providers';

export default component$(() => {
  useMatProviders({
    icon: {fontSet: 'material-symbols-outlined'},
    formField: {appearance: 'outline'},
    errorStateMatcher: 'dirty',
  });
  return <Slot />;
});

useMatProviders() is a convenience that fans out to the individual hook for each key you pass (icon → useMatIconProvider(), formField → useMatFormFieldProvider(), …) — see its own entry point for the full list of keys. The set of keys you pass must stay the same across every render of the component that calls it (the VALUES may change freely); pass every setting you might ever want to configure up front, even if some start out as {}.

A component deeper in the tree that wants to override just ONE setting for its own subtree — without touching anything else — calls that setting's own hook directly instead of the combined one:

// some nested route, overriding only the tooltip defaults for this page
import {component$, Slot} from '@qwik.dev/core';
import {useMatTooltipProvider} from '@angular-community/qwik-material/tooltip';

export default component$(() => {
  useMatTooltipProvider({showDelay: 500});
  return <Slot />;
});

The formField/icon settings from the root layout above are still inherited here — only the tooltip default changed.

Fonts and global CSS

Angular Material ships a Roboto font recommendation and a Material Symbols/Icons webfont for <mat-icon>'s default ligature mode; qwik-material is no different — load them yourself (there's no automatic injection):

<link rel="preconnect" href="https://fonts.gstatic.com" />
<link href="https://fonts.googleapis.com/css2?family=Roboto:wght@300;400;500&display=swap" rel="stylesheet" />
<link href="https://fonts.googleapis.com/css2?family=Material+Symbols+Outlined&display=block" rel="stylesheet" />

Import the global CSS once, at your root: qwik-material's core-prebuilt.css (the design tokens, typography, ripple and focus-indicator styles every component relies on) and qwik-cdk's overlay-prebuilt.css (needed by anything that opens an overlay — menu, select, autocomplete, datepicker, dialog, tooltip, snack bar, bottom sheet, …):

import '@angular-community/qwik-cdk/overlay-prebuilt.css';
import '@angular-community/qwik-material/core-prebuilt.css';

That's all: each component brings its own CSS when it renders, as Angular Material attaches a component's styles when the component is first created. A server-rendered page carries the CSS of the components it renders, once each, and a component first rendered in the browser (a dialog, a menu) brings its CSS with its own code. Like Angular Material's (ViewEncapsulation.None), that CSS is global, not scoped to the component — and all of qwik-material's CSS sits in one cascade layer, @layer qwik-material, so any rule of your own (outside a layer) beats it, whatever its specificity or where it loads. No Sass or Vite configuration is needed for qwik-material's CSS: it ships compiled, as a string in each entry point's TypeScript.

qwik-cdk is different: <QwikCdkRoot> auto-loads scss/overlay/overlay-structure-layered.scss by default (its loadStyles prop, default true), and CdkDialogContainer (used by useMatDialog()) imports scss/dialog/dialog-container-layered.scss unconditionally. Both resolve under the qwik export condition (see Migrating from Angular Material for the Vite setup that condition needs), so your own Vite build compiles them, and your app needs a sass dev dependency for that. This is pre-existing — the files were already .scss before this port's cascade-layer work. overlay-prebuilt.css above already carries the same structural CSS, so the auto-load is a duplicate: pass loadStyles={false} to <QwikCdkRoot> to skip it and drop the Sass requirement for the overlay structure (the dialog container's .scss import is unconditional and has no equivalent opt-out).

Render your first component

import {component$} from '@qwik.dev/core';
import {MatButton} from '@angular-community/qwik-material/button';

export default component$(() => <MatButton appearance="filled">Hello</MatButton>);
